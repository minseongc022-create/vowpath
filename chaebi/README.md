# 채비 (Chaebi)

> 검색하지 마세요. 상황만 말하세요.

기존 앱들은 **무엇을 하려는지 이미 아는 사람**을 위한 도구다. 식당 예약은 예약앱,
물건은 쇼핑앱, 업체는 중개앱. 채비는 반대다 — "내일 여자친구 생일인데 아무것도
준비 못했어" 한 줄이면, 필요한 걸 판단하고 찾고 예약·주문하고 진행까지 관리한다.

첫 버티컬은 **기념일·데이트 준비**다. 감정적 절박함이 크고, 반복 주기가 있고,
각 하위 카테고리에 이미 온라인 예약/결제 인프라가 있어서 오케스트레이션의 가치가
가장 잘 드러나는 영역이다.

경로: `/chaebi` · 다른 제품(효이로드·자비스·마노·토픽·런)과 코드·라우팅·저장소를
하나도 공유하지 않는 독립 제품이다.

---

## 흐름

```
말 한 줄
  │
  ├─ parse.ts          규칙 파서(항상) + LLM 덧칠(있으면) → SituationBrief
  │                    무슨 일 / 누구 / 언제 / 어디 / 얼마 / 무엇이 필요한가
  ▼
plan-engine.ts         예산 배분 → 항목 선정 → 총액 맞추기 → 업그레이드 → 동선
  │                    (후보 점수는 recommend.ts)
  ▼
확인 화면              사용자는 버튼 하나만 누르면 된다 (수정은 전부 선택 사항)
  │
  ▼
fulfillment.ts         예약·주문 실행. 막히면 대안으로 자동 교체.
  │                    상태는 (확정 시각, 지금)으로부터 계산 — 크론이 없어도 흐른다
  ▼
진행 화면              항목별 상태 · 예약번호 · 당일 동선
```

## 파일 지도

| 파일 | 하는 일 |
|---|---|
| `lib/types.ts` | 도메인 모델. 중간 산출물을 전부 타입으로 남긴다 |
| `lib/parse-rules.ts` | 한국어 규칙 파서. **LLM 없이도 앱이 온전히 돈다** |
| `lib/parse.ts` | 규칙 결과 위에 LLM을 필드 단위로 덧칠 (실패는 조용히 무시) |
| `lib/catalog.ts` | 시범 카탈로그 (가상 상호). 제휴 API가 들어올 자리의 명세 역할 |
| `lib/regions.ts` | 지역 별칭 매칭 + 이웃 지역 폴백 |
| `lib/recommend.ts` | 후보 점수 — 취향·예산·평점·표본·거리 |
| `lib/plan-engine.ts` | 예산 배분, 총액 맞추기, 동선 구성 |
| `lib/fulfillment.ts` | **제휴사 커넥터 경계.** 지금은 SimulatedConnector |
| `lib/store.ts` | KV → 파일 → 메모리 순 폴백 |
| `lib/owner.ts` | 로그인 없는 익명 소유자 쿠키 (미들웨어가 심는다) |

## 설계에서 양보하지 않은 것들

**시간은 점수가 아니라 필터다.** 오늘 저녁 자리에 24시간 걸리는 케이크를
추천하는 순간 앱이 거짓말을 한 게 된다. 후보 선정(`isFeasible`)과 확정 직전
점검(`stillFeasible`)이 **같은 기준(자리 시작 시각)** 을 쓴다.

**예산 한도는 총액이지 항목별 상한이 아니다.** 항목별로 칼같이 나눠 상한을 걸면
4만6천원짜리 동네 케이크집이 3만5천원짜리 기프티콘한테 진다. 배분은 안내선으로
쓰고, 총액은 `trimToBudget`이 지킨다.

**말한 지역 밖으로 새지 않는다.** "강남에서"라고 한 사람의 계획에 성수 식당이
들어가면 그날 지하철을 한 번 더 타는 건 사용자다. 자동 선택은 지역 안에서만
하고, 이웃 지역은 "다른 곳 보기"에서 사용자가 직접 넓힐 때만 나온다.

**대신 처리하는 것과 마음대로 쓰는 것은 다르다.** 예약이 막혀 대안으로 옮길 때도
총액이 예산 안에 남는 후보를 먼저 고르고, 그런 게 없을 때만 넘기면서 넘겼다고
밝힌다.

**상태는 저장하지 않고 계산한다.** 서버리스에 상주 프로세스가 없어 크론으로
상태를 밀면 크론이 죽는 순간 진행이 멈춘다. `advancePlan(plan, now)`은 몇 번을
불러도 같은 답을 준다.

## 실행 계층 — 진짜 예약을 붙일 때

지금 기본값은 `SimulatedConnector`다. **실제 예약을 걸지 않고**, 화면에도 그렇게
밝힌다(`plan.liveFulfillment === false`). 제휴가 붙으면:

1. `PartnerConnector`를 구현한다 (`reference`, `stages`).
2. 부팅 시 `registerConnector(new YourConnector())`.
3. `CHAEBI_LIVE_PARTNERS=1`.

위쪽 코드(엔진·라우트·화면)는 한 줄도 안 바뀐다.

## 환경 변수

전부 선택 사항이다. 하나도 없어도 앱은 켜지고 끝까지 돈다.

| 변수 | 없으면 |
|---|---|
| `OPENAI_API_KEY` | 규칙 파서만 쓴다 (뉘앙스 인식이 약해질 뿐) |
| `CHAEBI_OPENAI_MODEL` | 저장소 기본 모델 |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | 파일(로컬) 또는 메모리에 저장 |
| `CHAEBI_LIVE_PARTNERS` | 시범 모드 (실제 예약 안 걸림) |

## 개발

```bash
npm run dev                                  # http://localhost:3000/chaebi
npx tsx --test tests/unit/chaebi-engine.test.mjs
npm run chaebi:icons                         # public/chaebi/icon.svg → PWA 아이콘
```

`/chaebi`는 PWA로 설치된다 (`public/chaebi/site.webmanifest`) — 홈 화면에 추가하면
주소창 없이 앱처럼 뜬다.
