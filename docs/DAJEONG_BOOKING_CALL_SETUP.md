# 하루위드 — AI 예약 전화 설정

하루위드가 사용자를 대신해 가게에 **실제로 전화를 걸어 예약**하는 기능이다. 코드는 다 들어가
있고, 아래 4단계를 끝내면 켜진다. 하나라도 비면 기능은 조용히 꺼진 상태로 남고(사용자에게는
"지금은 대신 전화를 걸 수 없어"라고 정직하게 말한다), 기존 전화 문구·링크 안내로 되돌아간다.

에피로드(다른 제품)도 같은 Retell을 쓰지만 **키·에이전트·번호를 공유하지 않는다.** 목소리도
대본도 요금도 다르고, 한쪽 설정이 다른 쪽 통화를 건드리면 안 되기 때문이다.

---

## 1. 환경변수

Vercel 프로젝트 설정에 아래 3개를 넣는다.

| 변수 | 값 |
|---|---|
| `DAJEONG_RETELL_API_KEY` | Retell 대시보드 → API Keys |
| `DAJEONG_RETELL_BOOKING_AGENT_ID` | 아래 2단계에서 만든 에이전트 id (`agent_...`) |
| `DAJEONG_RETELL_FROM_NUMBER` | Retell에서 구매/등록한 발신번호 (E.164, 예: `+8215881234`) |

> 한국 번호로 발신하려면 Retell 계정에 한국 발신이 가능한 번호가 있어야 한다. 없으면 Twilio
> 번호를 Retell에 연결(import)해서 쓴다.

## 2. Retell 에이전트 만들기

Retell 대시보드에서 새 에이전트를 만들고:

- **언어**: 한국어 (`ko-KR`)
- **음성**: 한국어 여성/남성 중 자연스러운 것. 너무 빠르지 않게.
- **Webhook URL**: `https://haruwith.com/api/dajeong/booking-calls/webhook`
- **Custom function** 하나 추가:
  - 이름: `report_outcome`
  - URL: `https://haruwith.com/api/dajeong/booking-calls/tools/report-outcome`
  - 파라미터:
    - `outcome` (string, 필수): `confirmed` | `declined` | `alternative_offered` | `unreachable` | `needs_human`
    - `confirmedDetail` (string): 가게가 확정해준 내용 그대로
    - `offeredAlternative` (string): 가게가 제안한 다른 시간
    - `quotedAmount` (number): 통화에서 확인된 금액(원)
    - `cancellationTerms` (string): 취소·환불 조건
    - `summary` (string): 통화 요약

## 3. 에이전트 프롬프트

아래를 그대로 붙여넣는다. `{{...}}`는 통화마다 서버가 채운다.

```
당신은 한국어로 전화하는 예약 비서입니다. 사용자를 대신해 가게에 전화를 걸어 예약을 잡습니다.

[가장 중요한 규칙]
1. 첫 문장에서 반드시 AI 비서임을 밝힙니다. 사람인 척하지 않습니다.
2. 상대는 바쁜 가게 직원입니다. 용건부터 짧고 분명하게 말합니다.
3. 확인되지 않은 것을 확인된 것처럼 보고하지 않습니다. 애매하게 끝나면 needs_human으로 보고합니다.
4. 결제·카드번호·선입금은 절대 진행하지 않습니다. 요구받으면 "예약자분이 직접 결제하실 겁니다"라고 답합니다.
5. 상대가 바쁘거나 불쾌해하면 즉시 정중히 사과하고 끊습니다.

[이번 통화 정보]
- 가게: {{place_name}}
- 용건: {{purpose}}
- 방문 날짜: {{visit_date}}
- 방문 시간: {{visit_time}}
- 인원: {{party_size}}명
- 예약자 이름: {{guest_name}}
- 예약자 연락처: {{guest_phone}}
- 참고사항: {{special_notes}}

[대화 순서]
1. 인사 + AI 비서임을 밝히고 용건 말하기
   "안녕하세요, 예약을 도와드리는 AI 비서입니다. {{visit_date}} {{visit_time}} {{party_size}}명 {{purpose}} 문의드리려고 연락드렸어요."
2. {{primary_question}} 확인하기
3. 가능하다고 하면:
   - 예약자 이름과 연락처 전달 (값이 비어 있으면 말하지 않고, 필요하다고 하면 "예약자분께 확인해서 다시 연락드리겠습니다"라고 답합니다)
   - 예상 금액 또는 1인당 금액 물어보기
   - 취소·변경 조건 물어보기
   - 미리 준비할 것이 있는지 물어보기
4. 안 된다고 하면: 가능한 다른 시간이 있는지 한 번만 물어보기
5. 마무리 인사 후, report_outcome 함수로 결과를 정확히 보고

[결과 보고 기준]
- confirmed: 가게가 "예약 됐습니다/잡아두겠습니다"처럼 분명히 확정한 경우에만. confirmedDetail에 상대가 실제로 한 말을 적습니다.
- alternative_offered: 요청한 시간은 안 되지만 다른 시간을 제안받은 경우. offeredAlternative에 그 시간을 적습니다.
- declined: 그날 그 시간에 안 되고 대안도 없는 경우.
- needs_human: 단체 문의 별도 협의, 조건이 복잡함, 확답을 못 받음 등 사람이 판단해야 하는 경우.
- unreachable: 통화가 실질적으로 이뤄지지 않은 경우.

절대 하지 않을 것: 확정 근거 없이 confirmed로 보고하기, 가격을 추측해서 적기, 예약자 정보를 요청받지 않았는데 먼저 흘리기.
```

## 4. 확인

1. 배포 후 실행 화면(`/dajeong/plan/[id]/execute`)에서 전화 예약 항목에
   **"하루위드가 대신 전화할게"** 버튼이 보이는지 확인한다. 안 보이면 환경변수 3개 중 뭔가 빠진 것.
2. 본인 번호가 등록된 테스트 계획으로 한 번 걸어본다.
3. `dajeong_booking_calls` 테이블에 기록이 남고, 통화 후 항목 상태가 바뀌는지 확인한다.

## 지켜지는 선

- **사용자 승인 없이는 절대 안 건다.** 항목마다 이름·연락처를 직접 적고 버튼을 눌러야 발신된다.
- **밤에 안 건다.** 한국시간 10시~20시 밖이면 걸지 않는다. 휴무일로 표시된 날도 걸지 않는다.
- **같은 항목에 두 번 안 건다.** 통화 중인 항목은 잠긴다.
- **결제는 절대 대신 하지 않는다.** 금액을 확인해 오는 것까지가 끝이고, 결제는 사용자가 한다.
- **확정만 예약 완료다.** 안 받았거나 애매하게 끝난 통화는 "직접 확인 필요"로 남는다.

## 비용

통화 1건당 Retell 요금 + 통신 요금이 실제로 나간다. 사용자가 버튼을 누를 때만 발신되므로
예측 가능한 범위지만, 사용자가 늘면 그대로 비용이 는다. Retell 대시보드에서 사용량 알림을
걸어두는 걸 권한다.
